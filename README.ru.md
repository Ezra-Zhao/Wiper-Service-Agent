**Диалоговый ИИ-агент для клиентского сервиса автозапчастей — агент службы поддержки бизнеса стеклоочистителей**

**Мультитурный диалоговый агент** для реального малого бизнеса: клиент присылает в чат модель
автомобиля + год, агент подбирает размеры щёток стеклоочистителя, называет цену, отвечает на частые
вопросы (установка / гарантия / оплата), ведёт торг и фиксирует намерение заказа — готов к подключению
к WhatsApp-линии бизнеса.

> **Статус проекта: каркас v0.2 (честная редакция).**
> Полный цикл диалога сегодня работает на **симулированных** данных: мок-каталог применимости
> по автомобилям, настраиваемый демо-прайс, детерминированный rule-based заменитель NLU,
> rule-based определение языка и шаблонные многоязычные ответы (zh/en/es/ru/fa). Что реально:
> машина состояний диалога, интерфейсы инструментов, математика расчёта цен, правила определения
> языка и граница сообщений WhatsApp. Что пока TODO (явно помечено в коде): реальная база
> данных автомобилей, реальный прайс-лист, проверка шаблонов es/ru/fa носителями языка
> и продакшн-интеграция LLM + WhatsApp. Ничто здесь не притворяется, что принимает реальные заказы.

## Обзор

Цифровизация реального малого бизнеса (продажа стеклоочистителей + поддержка в WhatsApp) с помощью ИИ-агента:

- Клиент присылает модель и год → агент подбирает размер → называет цену → отвечает на FAQ → фиксирует намерение заказа
- Мультитурная машина состояний: приветствие → сбор данных об авто → подбор размера → цена/торг/вопросы → намерение заказа
- **Многоязычность v1**: автоматическое определение языка клиента (zh/en/es/ru/fa), весь диалог на языке клиента; JSON намерения заказа записывает `detected_language`
- Торг уступается только один раз (5%), FAQ не разрывают процесс продажи, по завершении автоматически генерируется JSON намерения заказа
- В будущем можно подключить к реальной линии WhatsApp (точки интеграции Baileys / whatsapp-web.js зарезервированы)

**Текущая демо-версия**: каталог автомобилей, прайс-лист и NLU — симуляция (в коде помечены SIMULATED и TODO);
перед запуском нужно заменить на реальную базу данных автомобилей и реальный прайс-лист.

```
                 |  WhatsApp message |
                 |  (phone, text)    |

                 +--------+----------+
                 |  WiperServiceAgent|  agent loop
                 |  + state machine  |
                 +---+---+---+---+---+
                     |   |   |   |
        +------------+   |   +------------+
        v                v                v
 +--------------+ +------------+ +--------------+
 | wiper_db     | | pricing    | | faq          |
 | size lookup  | | quoting    | | install/     |
 | (SIMULATED)  | | (config)   | | warranty/... |
 +--------------+ +------------+ +--------------+
        NLU: MockLLM (deterministic, SIMULATED)
        TODO: RealLLMProvider via function-calling
```

Состояния диалога: `GREETING → COLLECT_VEHICLE → QUOTE → DONE`
(FAQ отвечаются внутри QUOTE, поэтому процесс продажи никогда не прерывается.)

## Быстрый старт

```bash
cd Wiper-Service-Agent
pip install -r requirements.txt

python examples/demo.py        # 4 simulated customer conversations (中文 + Español)
python tests/run_tests.py     # 44 tests, no pytest needed
```

Демо-сценарии:
1. **Стандартный процесс** —— приветствие → автомобиль → FAQ по установке → заказ подтверждён
2. **Уточнение недостающего года** —— агент запрашивает недостающий год → торг → FAQ по гарантии → отказ
3. **Торг и вопросы** —— автомобиль уже в первом сообщении → торг о цене → FAQ по оплате → заказ подтверждён
4. **Полный процесс на испанском** —— приветствие на испанском → автомобиль → вопрос о цене → FAQ по установке → заказ подтверждён, всё на испанском (печатает распознанный язык)

Каждый сценарий печатает полную стенограмму плюс итоговый JSON намерения заказа (теперь включает `detected_language`).

## Продакшн-деплой (Render + Meta, запущен 2026-10-01)

`whatsapp/webhook_server.py` — webhook только на стандартной библиотеке: проверяет challenge Meta в GET, сверяет `X-Hub-Signature-256` в POST, прогоняет сообщения через агента и отвечает через Cloud API.

Переменные окружения (панель Render → Environment):

| Variable | Required | Purpose |
|---|---|---|
| `WA_VERIFY_TOKEN` | yes | token you set when subscribing the webhook in Meta |
| `WA_ACCESS_TOKEN` | yes | system-user token (`whatsapp_business_messaging`) |
| `WA_PHONE_NUMBER_ID` | yes | phone number ID of the business line |
| `WA_APP_SECRET` | strongly recommended | Meta App secret; enables `X-Hub-Signature-256` verification. Without it the server logs a loud warning and accepts unsigned POSTs |
| `WA_STORE_PATH` | no (default `./conversations.json`) | conversation persistence file. **Ephemeral on Render free tier** — a restart/sleep loses it; move to Postgres/Redis (same `ConversationStore` interface) when the business outgrows free |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | no | OpenAI-compatible endpoint for `RealLLMProvider`. Unset → deterministic `MockLLM` is used |
| `WA_API_VERSION` | no (default `v21.0`) | Graph API version |
| `PORT` | no (default `8000`) | listen port |

`RealLLMProvider` только *разбирает* сообщения в `ParsedMessage` (намерение/марка/модель/год/faq_topic) — он никогда не решает цены, размеры или условия сделки. Любой сбой сети/API/JSON автоматически откатывается на `MockLLM`.

## Многоязычность v1 (2026-10-01)

Бизнес стеклоочистителей обслуживает клиентов на китайском, английском, испанском, русском и персидском. Встроенный в WhatsApp перевод на устройстве **не** покрывает персидский, поэтому бот сам обрабатывает язык:

- **Определение** (`wiper_agent/language.py`): детерминированное, на правилах, без сети. Сначала письменность — CJK → китайский, кириллица → русский, арабское письмо →
  персидский/арабский (только персидские буквы گچپژیک vs только арабские ةىئؤء) — затем испанские символы/слова, затем общеупотребительные английские слова. Неизвестный
  ввод (например, просто "Toyota Camry 2018") по умолчанию считается китайским — языком владельца. Ненадёжные определения повышаются, когда следующее сообщение
  даёт более чёткий сигнал, а сообщения на том же языке фиксируют уверенность, так что случайное "OK" её не перевернёт.
- **Ответы** (`wiper_agent/i18n.py`): шаблонные, 5 языков (zh/en/es/ru/fa). Ввод арабским письмом, распознанный как арабский (ar),
  пока откатывается на английские шаблоны.
- **Честная граница**: шаблоны es/ru/fa — рабочие демо-переводы; **шаблоны fa — лишь минимальные ключевые фразы, перед продакшном нужна проверка носителем**.
  Продакшн-качество даст `RealLLMProvider` (пока TODO), генерируя ответы на языке клиента; шаблоны останутся запасным вариантом.
- **NLU** (`wiper_agent/llm.py`): мок-парсер намерений теперь распознаёт ключевые слова подтверждения/отказа/торга/цены/приветствия/FAQ на es/ru/fa
  (короткие слова вроде "да"/"sí" сопоставляются по границам слов, чтобы избежать ложных срабатываний внутри слов).

## Интеграция WhatsApp

`whatsapp/adapter.py` — транспортная граница: `(phone, text) -> reply text`.
`whatsapp/webhook_server.py` — продакшн-интеграция (webhook Meta Cloud API, задеплоен на Render — см. выше «Продакшн-деплой»). Хуки Baileys / whatsapp-web.js остаются задокументированными альтернативами в `adapter.py`.
